### なぜ調査タスクと相性がいいのか（0:30-1:30）

完全オートが調査タスクと相性がいい理由を説明します。

**1. ファイル探索に確認は不要**
grepやファイル検索で「見ますか？」と聞かれても意味がない。

**2. 思考の中断を防げる**
「このファイルも見ますか？」と聞かれると集中が切れる。

**3. 結果だけ欲しい**
途中経過より、最終レポートが欲しい。

調査タスクは「止まらず進んで、結果をまとめて」が理想的です。

---

### 調査用Steeringの使い方（1:30-3:00）

セクション3で紹介した調査用Steeringを使います。

チャット欄に以下を入力します。

```
#investigate 認証周りの実装を調査して
```

Kiroが動き始めます。

1. ディレクトリ構造を確認
2. エントリーポイントを特定
3. 依存関係を再帰的に追跡
4. 設定ファイルを確認
5. テストコードから仕様を読み取り
6. レポートを作成
7. `memo/investigation-YYYYMMDD-auth.md` に保存

私の入力は1回だけ。あとは100ファイル以上を自動で調査します。

---

### 調査が有効なケース（3:00-4:30）

調査が特に有効なケースを紹介します。

**1. 新しく参加したプロジェクトの理解**
「このプロジェクトの全体像を調査して」

**2. レガシーコードの把握**
「この機能の実装を調査して」

**3. 影響範囲の調査**
「このクラスを使っている箇所を調査して」

**4. セキュリティレビューの事前調査**
「認証・認可の実装を調査して」


---

### 調査後のアクション（4:30-5:30）

調査が終わったら、そのまま次のアクションに移れます。

```
#investigate このAPIの影響範囲を調査して

（調査完了）

#full-auto 調査結果を元にリファクタリングを進めて
```

調査 → 実装 の流れが自然につながります。

---

### 調査用Hooksの追加（5:30-6:30）

大規模調査では、進捗を報告するHookがあると安心です。

```json
{
  "name": "Investigation Progress",
  "version": "1.0.0",
  "when": {
    "type": "postToolUse",
    "toolTypes": ["read"]
  },
  "then": {
    "type": "askAgent",
    "prompt": "10ファイル以上読み込んだ場合、現在の進捗を簡潔に報告してください。"
  }
}
```

このHookを追加すると、調査中に進捗報告が入ります。
